# Huzl Meet Worker

`huzl` is the isolated Google Meet bridge used by the Huzlr Scrum Master. It polls
`huzlr-be` for due meeting jobs, joins with a persistent dedicated Google account,
captures meeting audio, reports lifecycle state, and responds to cancellation.

## Required configuration

```dotenv
HUZLR_BACKEND_URL=http://host.docker.internal:8001
HUZL_WORKER_KEY=<same long random value configured in huzlr-be>
BOT_PROFILE_DIR=/data/google-bot-profile
REQUIRE_BOT_PROFILE=true
HEADLESS=true
CHROME_EXECUTABLE_PATH=/Applications/Google Chrome.app/Contents/MacOS/Google Chrome
```

Create a worker key with a system password generator. Create the backend token
encryption key with:

```bash
python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

## Provision the dedicated account

Provisioning is intentionally interactive and uses a normal Google Chrome process so
Google credentials are never entered into an automated browser. Do not put the Google
password or a 2FA secret in environment variables or source control.

```bash
python3 provision_bot_profile.py /secure/path/google-bot-profile
```

Sign in through the opened Chromium window, then mount that directory at
`BOT_PROFILE_DIR` for one worker only. A Chromium profile must never be shared by
concurrent containers.

## Run

```bash
docker build -t huzl-worker .
docker run --rm \
  -e HUZLR_BACKEND_URL=http://host.docker.internal:8001 \
  -e HUZL_WORKER_KEY=... \
  -e BOT_PROFILE_DIR=/data/google-bot-profile \
  -e REQUIRE_BOT_PROFILE=true \
  -v /secure/path/google-bot-profile:/data/google-bot-profile \
  huzl-worker
```

## Current boundary

The worker covers scheduling, authenticated job claiming, persistent bot identity,
admission confirmation, LiveKit voice-agent audio bridging, heartbeats, cancellation,
bounded retries, and cleanup. Transcript persistence is handled by the backend agent.
Post-meeting summaries and proposed action items are generated by `huzlr-be` after
completion. Participant-level diarization and confirmed project writes remain disabled.
