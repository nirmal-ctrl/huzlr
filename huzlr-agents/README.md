# Huzlr Agents

Persistent LiveKit workers are deployed from this module. The FastAPI service remains
request-driven on Vercel and communicates with these workers through explicit LiveKit
dispatch and the protected internal agent API.

## Agent types

| Type | LiveKit dispatch name |
| --- | --- |
| `brainstorm` | `huzlr-brainstorm` |
| `founder` | `huzlr-founder` |
| `scrum_master` | `huzlr-scrum-master` |

One image serves every agent type. Each LiveKit deployment sets `HUZLR_AGENT_TYPE` to
select its worker at startup, which keeps deployments and scaling independent without
duplicating the image definition.

## Scrum Master voice modes

Choose **Standard** or **Gemini Live — speech-to-speech** under Scrum Master settings
in the Huzlr web app. The choice belongs to the workspace and is captured when the
Meet worker claims a meeting; changing settings does not switch an active call.
Both modes use the same `scrum_master` worker and `huzlr-scrum-master` dispatch name.

- `pipeline` (default): Silero VAD → Deepgram STT → Gemini 2.5 Flash → Deepgram Aura-2.
- `gemini_live`: Gemini Live consumes audio and generates audio directly, with its
  built-in turn detection. No separate Deepgram STT, TTS, or Silero VAD is started.
  Input/output transcription is enabled for the existing transcript persistence.
  The same scoped project tools and meeting prompt apply to both modes.

Gemini Live requires `GOOGLE_API_KEY` (or `GEMINI_API_KEY`) in the agent environment.
`GEMINI_LIVE_MODEL` defaults to `gemini-3.8-live`, and `GEMINI_LIVE_VOICE` defaults
to `Puck`; override them in `.env` when needed. Model access and quota must be
available on that Google API project. The introduction is generated by the native
audio model, so exact wording is not guaranteed. Context-window compression and
the Google plugin's session resumption support longer meetings.

To roll out this option, apply the backend migration through `d4e5f6a7b8c9`,
rebuild/redeploy the agent image with the updated LiveKit 1.8.2 packages, and then
deploy the backend and frontend. The Meet bridge needs no changes or new credentials. Standard
remains the default for existing workspaces. Run a controlled meeting in each mode
to compare end-of-speech to first audible response and verify interruption,
transcripts, project tools, and summaries; native audio does not guarantee a specific
end-to-end latency.

Integration references: [LiveKit Gemini Live plugin](https://docs.livekit.io/agents/models/realtime/plugins/gemini/)
and [Google Live API capabilities](https://ai.google.dev/gemini-api/docs/live-api/capabilities).

## Local development

Create `.env` from `.env.example`, then install the package into a virtual environment:

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m livekit.agents download-files
PYTHONPATH=src HUZLR_AGENT_TYPE=brainstorm .venv/bin/python -m huzlr_agents.runner dev --no-reload
```

Founder and Scrum Master additionally require `HUZLR_API_URL` and
`HUZLR_AGENT_SERVICE_KEY`. The service key must match `AGENT_SERVICE_KEY` in FastAPI.

## LiveKit Cloud deployments

Authenticate and select the LiveKit project first:

```bash
lk cloud auth
lk project set-default "<project-name>"
```

Create the two new deployments from this directory. Provide all provider and LiveKit
secrets through a non-committed secrets file, plus the agent type shown below:

```bash
lk agent create --config livekit.brainstorm.toml --secrets-file .env --secrets HUZLR_AGENT_TYPE=brainstorm .
lk agent create --config livekit.founder.toml --secrets-file .env --secrets HUZLR_AGENT_TYPE=founder .
```

The existing Scrum Master deployment configuration was moved to
`livekit.scrum-master.toml`:

```bash
lk agent deploy --config livekit.scrum-master.toml --secrets-file .env --secrets HUZLR_AGENT_TYPE=scrum_master .
```

For later releases, deploy each configuration independently with `lk agent deploy`.
